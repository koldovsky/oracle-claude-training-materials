# Claude Code + Oracle — навчальне середовище

Репозиторій курсу: каталог схем навчальної бази, матеріали занять і скрипти розгортання.

Дані **виключно синтетичні** — офіційні демонстраційні схеми Oracle.
Реальних чи конфіденційних даних тут немає.

---

## Підготовка робочого місця

П'ять кроків, приблизно 15 хвилин. **Під кожним кроком написано, що саме ви
маєте побачити.** Не збіглося — не йдіть далі, напишіть тренеру.

**Що потрібно мати заздалегідь:**

- Claude Code — встановлений, ви в нього увійшли
- Oracle SQLcl (потребує Java 21) і Git
- Від тренера: ваш логін, ваш пароль, файл `Wallet_ACORDTRAIN.zip`

> **Wallet не розпаковуйте.** SQLcl читає його прямо з архіву. Розпакування плюс
> змінна `TNS_ADMIN` — найчастіша причина помилки `ORA-12506`.

---

### Крок 1 · Перевірте, що інструменти на місці

Відкрийте **Git Bash** (Пуск → Git Bash), не PowerShell.

```bash
claude --version
sql -V
git --version
```

**Очікується:** три номери версій. Конкретні цифри значення не мають — важливо,
що жодна команда не сказала `command not found`.

> Чому саме Git Bash: у PowerShell немає `grep`, а його замінник `Select-String`
> за замовчуванням **не розрізняє регістр**. На занятті це має значення.

---

### Крок 2 · Перевірте каталог схем

```bash
ls db/CO db/HR
```

**Очікується** — два переліки підкаталогів (розкладка в колонки чи в стовпчик
залежить від ширини вікна, це не важливо):

- у `db/CO` — `indexes`, `tables`, `views`
- у `db/HR` — `indexes`, `procedures`, `sequences`, `tables`, `triggers`, `views`

Це робочий каталог першої половини заняття — 63 файли DDL схем HR і CO.
Перевірити кількість: `find db -name '*.sql' | wc -l` має дати **63**.

---

### Крок 3 · Збережіть з'єднання з базою

**Це найважливіший крок, і його легко пропустити.**

Claude Code ходить у базу не через ваш термінал, а через власний процес SQLcl —
вашого відкритого сеансу він не бачить. Тому з'єднання має бути збережене
разом із паролем.

```bash
sql -cloudconfig C:/шлях/до/Wallet_ACORDTRAIN.zip /nolog
```

**Очікується:** запрошення `SQL>` без підключення до бази.

Далі, у цьому ж запрошенні:

```
connect -save train -savepwd ВАШ_ЛОГІН@acordtrain_low
```

**Очікується:** запит пароля (так він не осяде в історії команд), потім
повідомлення про успішне підключення.

> Прапорець `-savepwd` **обов'язковий**. Без нього з'єднання створиться і
> працюватиме у вас у терміналі, але Claude Code скористатися ним не зможе —
> і вся друга половина заняття не працюватиме.

---

### Крок 4 · Перевірте збережене з'єднання

Вийдіть із SQLcl (`exit`) і виконайте:

```bash
sql -S -name train
```

**Очікується:** підключення **без запиту пароля**. Питає пароль — крок 3 не
спрацював, поверніться до нього.

Далі:

```sql
select user from dual;
select count(*) from hr.employees;
```

**Очікується:** ваш логін і число **107**.

---

### Крок 5 · Перевірте ланцюг через Claude Code

Вийдіть із SQLcl. У корені репозиторію запустіть `claude` і спитайте:

> скільки рядків у HR.EMPLOYEES

**Очікується:** Claude просить дозвіл на MCP-сервер `sqlcl` — підтвердіть —
і повертає **107**.

Збіглося — ви готові до заняття.

## Що в репозиторії

```
db/           Каталог схем HR і CO — 63 файли DDL.
              Тут шукають, читають чужий код і оцінюють наслідки змін.
training/     Матеріали заняття
setup/        Скрипти розгортання бази (виконує тренер, один раз)
.mcp.json     Опис MCP-сервера SQLcl
```

`.mcp.json` лежить у репозиторії навмисно: завдяки цьому підключення однакове
у всіх, без ручного налаштування. Тому `claude` треба запускати **з кореня
репозиторію** — інакше він цього файлу не побачить.

---

## Що в базі

| Схема | Вміст | Доступ |
|---|---|---|
| **HR** | Кадри: 7 таблиць, 107 працівників. **2 процедури і 2 тригери** — це весь PL/SQL бази | читання |
| **CO** | Замовлення: 7 таблиць, 1 950 замовлень, 4 в'юхи. Деталі товару — BLOB з обмеженням `IS JSON` | читання |
| **SH** | Продажі: 9 таблиць, 918 843 рядки в `SH.SALES`. **Індексів і партиціонування немає** | читання |
| **Ваша схема** | Порожня, повний доступ, квота 1 ГБ | читання і запис |

Ваша схема називається так само, як ваш логін.

### Ізоляція

Кожен бачить лише свою схему. Спроба звернутися до чужої дає
`ORA-00942: table or view does not exist` — саме «не існує», а не «немає
доступу»: Oracle навмисно не дає вивідати склад бази.

HR і CO захищені від запису — спроба дасть `ORA-01031`.

### Якщо берете `SH` для домашнього завдання

На `SH.SALES` немає жодного індексу, і створити його там ви не зможете —
схема лише на читання. Щоб дійти до `index range scan`, скопіюйте таблицю до себе:

```sql
create table my_sales as select * from sh.sales;
```

Копія займе **36 МБ**, з одним індексом — **53 МБ**. Квота 1 ГБ, тож запас великий.
(Оригінал на диску лише 3 МБ, бо стиснутий — не орієнтуйтеся на цю цифру.)

## Альтернатива: GitHub Codespaces

Якщо ставити SQLcl і Java на робоче місце незручно, середовище піднімається
у хмарному контейнері, де все це вже є. Кроки 1, 3 і 4 з початку файлу тоді
не потрібні — `post-create.sh` робить їх сам.

**Спершу додайте два особисті секрети:** GitHub Settings → Codespaces → Secrets
→ New secret, у полі **Repository access** оберіть цей репозиторій.

| Секрет | Значення |
|---|---|
| `ADB_USER` | ваш логін, напр. `TRAINEE1` — видає тренер |
| `ADB_PASSWORD` | ваш пароль — видає тренер |

> **Чому саме на рівні користувача.** Якби логін і пароль лежали на рівні
> репозиторію, усі підключалися б під одним обліковим записом в одну схему —
> ізоляція, заради якої все будувалося, зникла б.

Далі **Code → Codespaces → Create codespace on main**. Перша збірка 3-5 хвилин.

> ### Вхід у Claude Code всередині Codespaces
>
> Браузер поверне код автентифікації на `http://localhost:<порт>`, а цей порт до
> контейнера не прокидається — сторінка не відкриється. **Це нормально.**
>
> З адреси, на якій браузер спіткнувся, візьміть `code` і `state` та вставте
> в термінал на запит `Paste code here if prompted >`, з'єднавши решіткою:
>
> ```
> <code>#<state>
> ```
>
> Код живе кілька хвилин. Не встигли — `/login` заново.

Спільні секрети рівня репозиторію (`ADB_WALLET_B64`, `ADB_SERVICE`) налаштовує
тренер один раз: wallet прив'язаний до бази, а не до користувача.

## Якщо не працює

| Симптом | Причина і що робити |
|---|---|
| `ORA-12506` | Wallet не підхопився. Найчастіше — розпакували архів і виставили `TNS_ADMIN`. Виконайте `unset TNS_ADMIN` і підключайтесь через `-cloudconfig` до самого zip |
| `sql -S -name train` питає пароль | З'єднання збережене без `-savepwd`. Поверніться до кроку 3 — інакше Claude Code не підключиться |
| Таймаут при підключенні | Закритий вихідний порт **1522**, або база зупинена (безкоштовний тариф зупиняє її після тривалої бездіяльності) |
| `ORA-01017` | Логін або пароль. Пароль чутливий до регістру |
| `ORA-00942` на чужу схему | Так і має бути — це ізоляція, а не помилка |
| Claude Code не бачить MCP-сервера | Запускайте `claude` з кореня репозиторію, де лежить `.mcp.json` |
| `grep` не знайдено | Ви в PowerShell. Відкрийте Git Bash |

## Безпека

- Тільки офіційні демонстраційні схеми Oracle — жодних реальних даних
- Паролі й wallet роздаються персонально, **не через цей репозиторій**
- `.gitignore` перекриває wallet-файли, каталог секретів і матеріали з доступами
- Телеметрія Claude Code вимкнена (`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`)

**Wallet — це облікові дані.** Разом із паролем він дає повний доступ до бази.
Не пересилайте його у відкритих чатах і не комітьте.
