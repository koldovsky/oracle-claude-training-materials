# Джерела та межі розширень

Перевірено **15 вересня 2026 року** за офіційною документацією Claude Code.
Файли призначено для Claude Code; конфігурація Codex не створюється.

| Джерело | Що звірено |
|---|---|
| [Skills](https://code.claude.com/docs/en/skills) | `.claude/skills/<name>/SKILL.md`, YAML `name`, `description`, `argument-hint`, `allowed-tools`, виклик `/oracle-lab-review`, `$ARGUMENTS` і окремі references |
| [Subagents](https://code.claude.com/docs/en/sub-agents) | `.claude/agents/`, список `tools` обмежує набір інструментів; `skills` завантажує навик у контекст; історія головного агента не передається автоматично |
| [Hooks](https://code.claude.com/docs/en/hooks) | `PreToolUse`, regex `matcher`, stdin JSON, поля Write/Edit, shell `bash`, `${CLAUDE_PROJECT_DIR}`, exit 2 для блокування та exit 0 без рішення |

## Що демонструє комплект

`sql_guard.py` відтворює майбутній вміст SQL-файлу після `Write` або `Edit`
і шукає `DROP`, `TRUNCATE`, `ALTER SYSTEM`, включно з простими літералами
`EXECUTE IMMEDIATE`. Область — лише файли з розширенням `.sql` усередині
`lab/` поточного `CLAUDE_PROJECT_DIR` після нормалізації шляхів. Зміни Markdown,
налаштувань та файлів за межами `lab/` не фільтруються. Неповний/пошкоджений
JSON Write/Edit, відсутній корінь і помилки читання перевірюваного SQL-файлу
блокуються з exit 2. Допустимий виклик повертає порожній stdout і exit 0.

Це **демонстраційна перевірка запису файлів**, не SQL-парсер чи межа безпеки.
Коментарі й рядки можуть дати хибне блокування. Обфускований динамічний SQL
не розпізнається повністю. Bash, PowerShell, MCP, SQLcl, ручні зміни,
інші розширення файлів, симлінки за межі `lab/` та інші канали не контролюються.
Права користувача Oracle й ізоляція навчальної схеми визначають доступ до БД.
Заборонений пакетним контрактом `COMMIT` перевіряється рев'ю і SQL-тестом;
цей hook навмисно не охоплює всі стандарти коду.

Якщо інтерпретатор або скрипт не запустився чи сплив timeout, command hook
може не заблокувати інструмент. Спочатку виконай локальне демо, а в Claude Code
перевір завантаження через `/hooks` і покажи блокування реального `Write`.
[Правила помилок і timeout](https://code.claude.com/docs/en/hooks#exit-code-output)
пояснюють цю межу.

## Запуск у навчальному workspace

Кореневий `setup-workspace.py` копіює цей `.claude/` в окремий workspace.
Запусти Claude Code з його каталогу після копіювання файлів. Навик доступний
як `/oracle-lab-review lab/settlement.pkb.sql`; точний файл для рев'ю
звір із переліком `lab/`. Для агента доручи: «Використай oracle-reviewer для
незалежного рев'ю пакета в lab/. Файлів не змінюй».

У терміналі workspace:

```text
python --version
python .claude/hooks/demo.py
```

Потрібен Python **3.10+** з командою `python` у PATH. Конфігурація використовує
Bash: Linux/Codespaces або Git Bash на Windows. Для Windows без Git Bash
цей варіант конфігурації не призначений. Шлях до скрипту взято в лапки;
обидва Python-скрипти працюють із пробілами та кирилицею в шляхах.

Очікується шість PASS для payload-сценаріїв, PASS для незмінності тимчасового
файлу і код завершення демо 0. Це доводить поведінку Python-hook на підготовлених
входах; його реєстрація у Claude Code потребує окремої демонстрації.

Безпечне інтерактивне демо після `/hooks`:

1. Попроси Claude створити `lab/hook_probe.sql` інструментом Write з рядком
   `SELECT 1 FROM dual;`. Перевір появу файлу.
2. Попроси замінити файл через Write текстом `DROP TABLE S2_ORDERS;`, **лише
   записати текст, не виконувати SQL**. Очікуй повідомлення `SQL guard` та
   заблокований запис; попередній SELECT має залишитися.
3. Якщо блокування не видно, зупини демо та виправ запуск hook; SQL не запускай.

`allowed-tools` навику — попередній дозвіл на перелічені інструменти, а не
повна ізоляція; навик містить інструкцію лише читати. В агента `tools: Read,
Grep, Glob` саме звужує доступ: shell, запис і MCP відсутні.
