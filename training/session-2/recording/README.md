# Запис демонстрацій Сесії 2

**Інструкція для тренера.** Тут створюється запис справжніх подій Claude Code і
SQLcl для перегляду в браузері. Це відтворення журналу з play/pause і перемотуванням,
а не відеозахоплення екрана.

Ланцюг роботи:

```text
синтетична робоча тека + промпт
    → record_demo.py → локальні сирі журнали
    → перевірка результату → sources.json
    → build_rehearsal.py + lesson.json → очищений JSON + автономний HTML-урок
```

Запис містить розбір і можливу реалізацію вправи. На занятті показуйте відповідний
фрагмент після самостійної спроби учасників.

## 1. Підготуйте робочу теку й промпт

Потрібні Python 3.10+, Git і вже авторизований Claude Code. Для окремої демонстрації
MCP також потрібні SQLcl та особисте збережене з'єднання `train`.

Усі команди цієї інструкції виконуються **з кореня репозиторію**:

```bash
python training/session-2/setup-workspace.py training/session-2/workspace-recording
```

Наявна тека не перезаписується. Вона містить власний Git-репозиторій із початковим
станом, потрібні розширення та синтетичну лабораторію; тренерський еталон не копіюється.
Нова тека не створює новий обліковий запис Oracle: `train` усе ще веде до тієї самої схеми.

Створіть локальний UTF-8 файл, наприклад
`training/session-2/.rehearsal/recording-prompts/skill-take-02.txt`:

```text
Використай Skill oracle-lab-review для lab/settlement.pkb.sql.
Перевір за lab/SPEC.md. Наведи підтверджені порушення з файлом,
рядком, конкретним входом і способом перевірки.
Файлів не змінюй, SQL не виконуй. Окремо зазнач неперевірене.
```

Для нового дубля обирайте нове ім'я. Старі записи залишаються джерелом доказів.

## 2. Запишіть реальний прогін Claude

```bash
python training/session-2/recording/record_demo.py --name skill-take-02 --prompt training/session-2/.rehearsal/recording-prompts/skill-take-02.txt --workspace training/session-2/workspace-recording --timeout 240 --max-budget-usd 3
```

Ця команда справді викликає Claude через поточний авторизований CLI. Recorder не
передає `--model` і не встановлює інший модельний профіль. Фактично використану
модель дивіться у записі; не підставляйте її назву за припущенням.

Скрипт використовує `stream-json`, видимі події hook, проєктні налаштування та
визначений набір інструментів: читання, skill, agent, `Write` і `Edit`.
Нову постійну сесію CLI він не зберігає. Bash не входить до цього набору.
Ліміти часу й бюджету можна явно змінити параметрами.

### MCP — лише за окремим прапорцем

Без прапорця recorder передає **порожню** MCP-конфігурацію зі строгим режимом.
Для окремого дозволеного читання Oracle додайте:

```text
--with-sqlcl-mcp
```

Тоді перевіряється точна конфігурація `.mcp.json` згенерованої теки: тільки сервер
`sqlcl`, команда `sql`, аргумент `-mcp`. Інша конфігурація відхиляється.
У промпті задайте конкретний `SELECT` і з'єднання `train`.
Прапорець не перетворює сам SQLcl на технічно read-only сервер: межі операцій
визначають доручення та права навчального облікового запису.

Компіляцію й приймання зміненого пакета записують окремим SQLcl-прогоном.
Статичний висновок Claude не замінює його результат.

## 3. Перевірте сирий запис

За замовчуванням створюються чотири файли в ігнорованій Git теці
`training/session-2/.rehearsal/recordings/`:

| Файл | Вміст |
|---|---|
| `<ім'я>.prompt.txt` | фактичний промпт, переданий процесу |
| `<ім'я>.jsonl` | події CLI в обгортці `{elapsed, event}` |
| `<ім'я>.stderr.txt` | діагностика процесу |
| `<ім'я>.meta.json` | стан, код завершення, тривалість, число подій, SHA-256 журналу |

`elapsed` — час отримання події від початку процесу, виміряний монотонним
годинником. Він не зменшується. Промпт і фінальна подія `result` зберігаються
фактично, разом із наявними показниками CLI.

**Успіх:** нульовий код процесу, фінальний `result` із `subtype=success`,
відсутність помилки та коректний потік JSON. Друкується `RECORDING_PASS`.
Самого тексту «готово» у відповіді моделі недостатньо.

Відсутній результат, ненульовий код, помилковий JSON, не-об'єкт замість події,
тайм-аут або невдала передача промпта позначають запис як `failed`.
Не додавайте такий дубль до успішних демонстрацій, навіть якщо в ньому є корисний фрагмент.

При тайм-ауті recorder завершує лише дерево створеного ним процесу. Якщо Windows
відхилив `taskkill`, метадані містять `terminationConfirmed=false` і причину з
`termination_failed`; успішне завершення дерева тоді не підтверджене. Зупиніть
лише цей відомий процес у середовищі, де маєте потрібні права, перш ніж записувати далі.

## 4. Додайте успішний дубль до manifest

У [sources.json](sources.json) масив `runs` описує джерела, а `sections` — порядок
демонстрацій. Усі шляхи до журналів і промптів рахуються **від теки manifest**.

Приклад нового елемента `runs`:

```json
{
  "id": "skill-take-02",
  "title": "Рев'ю за контрактом",
  "subtitle": "Фактичний виклик skill",
  "kind": "claude",
  "source": "../.rehearsal/recordings/skill-take-02.jsonl",
  "promptFile": "../.rehearsal/recordings/skill-take-02.prompt.txt"
}
```

Додайте цей `id` до `runIds` потрібної секції або замініть попередній дубль.
Ідентифікатори мають бути унікальними. Текст мети й висновку секції повинен
відповідати тому, що фактично видно в обраному записі.

Нові записи мають сусідній `.meta.json`: importer перевіряє успішний стан,
нульовий код процесу та збіг `rawSha256`. Окреме поле manifest для метаданих
не потрібне. Старі сирі Claude JSONL без такого файла також підтримуються,
але це не дає права приписувати їм відсутні показники чи часові позначки.

### Окремі SQLcl-джерела

Для `kind=sqlcl` журнал повинен починатися фактичними даними запуску:

```text
LABEL=<назва> EXIT=<фактичний код> SECONDS=<виміряна тривалість>
COMMAND=<фактично виконана команда>
<фактичний stdout і stderr>
```

Це схема формату, а не готовий журнал. Значення отримують із запуску, а не
вписують бажані результати. `COMMAND` необов'язковий; за його відсутності
програвач не вигадує виконану команду з опису manifest.

У manifest задайте `source`, `kind`, `expectExit` та `expectMarker`.
Для приймання після зміни це код `0` і
`ACCEPTANCE_PASS: checks=18, unexpected=0`. Для початкового негативного прогону
очікується фактичний ненульовий код і маркер п'яти невідповідностей.
Код wrapper `run-lab.py` та код прямого SQLcl можуть відрізнятися — звіряйте
з реально використаною командою.

## 5. Зберіть автономну сторінку

```bash
python training/session-2/recording/build_rehearsal.py
```

За замовчуванням використовуються `sources.json`, `lesson.json` і
`rehearsal.template.html` з цієї теки. Результати:

- `tools/session-2-rehearsal.html` — автономний урок із поясненнями, записами й ZIP практики;
- `tools/session-2-rehearsal-data.json` — очищені структуровані дані для перевірки.

Є параметри `--manifest`, `--template`, `--html`, `--data` для окремого експорту.
Успіх позначається `REHEARSAL_READY`; відсутні або некоректні джерела завершують
збірку з помилкою. Скрипт не робить Git-комітів і не публікує сайт.

Відкрийте HTML локально й перевірте всі секції: промпт, виклики, відповіді,
фінальний результат, перемотування й повернення до початку.
Сторінка відтворює збережені події та не викликає Claude чи Oracle.

### Оновлення уроку без сирих журналів

У свіжому клоні публічного репозиторію сирих журналів немає. Для оновлення
пояснень або програвача використовуйте вже опубліковані очищені дані:

```bash
python training/session-2/recording/build_rehearsal.py --from-data tools/session-2-rehearsal-data.json
```

Цей режим перевіряє структуру даних і зберігає зафіксовані прогони. Текст уроку
та архів практики збираються заново з поточних відкритих джерел. Це не новий
запуск Claude або Oracle й не повторна перевірка походження сирих журналів.
Для додавання нових записів використовуйте звичайний режим із `sources.json`.

### Пояснення та практичні файли

Редагуйте [lesson.json](lesson.json), а не згенерований HTML. Урок має вступ,
підготовку, пояснення до й після шести секцій, завершальні вправи та словник.
Підтримуються абзаци, заголовки, списки, кроки, таблиці, код, примітки, посилання
й вкладені блоки `details`. Блок `source` бере актуальний текст дозволеного
публічного файла; ручне копіювання його вмісту не потрібне.

Пояснення відокремлені від фактичних кадрів. Вони можуть розбирати помилку в
записі, але не повинні переписувати відповідь агента або результат SQL.
Розкриття всіх пояснень не перемотує програвач і не відкриває записи з відповідями.
Для друку пояснення розкриваються; після друку їхній попередній стан відновлюється.

Кнопка ZIP працює без мережі: архів вбудований у HTML. Builder включає лише
визначені публічні файли, перевіряє збіг робочого пакета зі стартером і використовує
сталий порядок та часові позначки для відтворюваного результату. Структура архіву
повторює репозиторій: після розпакування почніть із `START-HERE.md` та виконайте
`python training/session-2/setup-workspace.py` з кореня розпакованої теки.
Архів не містить тренерського еталона, сирих журналів або збережених з'єднань.

**У публічну копію ніколи не переносять сирі `.jsonl`, `.stderr.txt`, `.prompt.txt`,
`.meta.json` чи всю `.rehearsal/`.** Експортуються лише перевірені HTML й очищений
JSON. Importer прибирає внутрішнє міркування, підписи та службові поля, маскує
відомі секрети й абсолютні локальні шляхи. Перед передачею все одно перегляньте
видимий текст: автоматичне маскування не пояснює контекст за тренера.

## Як читати час, токени й вартість

| Поле | Джерело й значення |
|---|---|
| Тривалість Claude | `duration_ms` фінального `result`, у секундах |
| Вартість | фактичний `total_cost_usd`, повідомлений CLI; не прогноз і не рахунок учасника |
| Вхідні токени | `inputTokens + cacheReadInputTokens + cacheCreationInputTokens` у `modelUsage` |
| Вихідні токени | окремий показник виходу з того самого фактичного результату |
| Перший вхід | вхід + створення кешу + читання кешу першого запиту основного агента |
| Прогін з агентами | агрегат, який повернув CLI; не видавайте його за витрати одного ізольованого запиту |
| SQLcl | тривалість із журналу; токени й вартість відсутні та показуються рискою |

Кешований вхід залишається контекстом і має окрему категорію використання.
Не називайте `inputTokens` без кешу всім контекстом. Невідоме значення — це не нуль.

**«Записаний час»** використовується для джерела, де кожна подія має `elapsed`.
**«Темп читання»** — умовні паузи програвача для старого журналу без цих позначок.
Другий режим не відтворює реальні паузи оригінального термінала; сумарна
виміряна тривалість у показниках залишається окремою величиною.

Програвач не домальовує екрани `/hooks`, `/context`, `/mcp` чи інші дії,
яких не було у джерелі. Окремі дублі не представляють одну безперервну сесію.

## Локальні тести без Claude

```bash
python -m unittest discover -s training/session-2/recording/tests -v
```

`test_recorder.py` запускає лише короткі фальшиві потоки через локальний Python:
перевіряє час, промпт, фінальні дані, помилки, відмову перезапису й тайм-аути.
Виклики recorder у тестах мають додатковий зовнішній тайм-аут 20 секунд.

На Windows два тести дерева процесів пропускаються, поки явно не дозволите їх
у середовищі, де `taskkill` може завершувати **власні тестові процеси**:

```powershell
$env:SESSION2_RUN_PROCESS_TREE_TEST = '1'
python -m unittest discover -s training/session-2/recording/tests -p test_recorder.py -v
```

Ці тести не завершують чужі програми. Вони використовують лише PID процесів,
які самі створили, і прибирають їх після перевірки.
